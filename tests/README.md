# آزمون‌های تاکورا

دو آزمون که پیش از هر انتشارِ مربوط به دسترسی باید سبز باشند. هر دو به
یک MySQL/MariaDB واقعی نیاز دارند — نه به سرور زنده، بلکه به یک نمونهٔ
موقت که چند دقیقه بالا می‌آید و دور انداخته می‌شود.

## چرا با دیتابیس واقعی

اسکیمای نسخهٔ ۶ دو تضمین امنیتی دارد که **فقط** در سطح دیتابیس اعمال
می‌شوند: یگانگی مالک پلتفرم، و دیوار مجوزهای سطح پلتفرم. هیچ آزمون
ایستایی نمی‌تواند ثابت کند این دو واقعاً کار می‌کنند؛ باید تلاش کرد
نقضشان کرد و دید که دیتابیس رد می‌کند.

## راه‌اندازی نمونهٔ موقت

```bash
mariadb-install-db --datadir=/tmp/tk-test/data --password="" --port=3399
mariadbd --defaults-file=/tmp/tk-test/data/my.ini --port=3399 --console &
```

اگر پورت یا مسیر دیگری خواستید:

```bash
export TALKORA_TEST_DSN="mysql:host=127.0.0.1;port=3399;charset=utf8mb4"
export TALKORA_TEST_DSN_DB="mysql:host=127.0.0.1;port=3399;dbname=talkora_test;charset=utf8mb4"
```

PHP باید `pdo_mysql` داشته باشد.

## اجرا

```bash
php tests/schema.php        # اول این — دیتابیس آزمون را می‌سازد
php tests/equivalence.php   # بعد این — روی همان دیتابیس کار می‌کند
```

هر دو با کد خروج غیرصفر شکست می‌خورند، پس در اسکریپت هم قابل استفاده‌اند.

### `schema.php` — ۲۵ بررسی

اسکیما را با **همان منطق تکه‌کردنی** اجرا می‌کند که `install.php` دارد
(تقسیم روی نقطه‌ویرگول، حذف خطوط توضیح). اگر دستوری زیر آن تقسیم بشکند،
اینجا معلوم می‌شود نه روی سرور مشتری.

بعد تلاش می‌کند تضمین‌ها را نقض کند و انتظار دارد رد شود:

- ساخت مالک پلتفرم دوم
- ارتقای یک ادمین عادی به مالک
- چسباندن مجوز سطح پلتفرم به یک نقش
- دور زدن همان با `is_platform=1`
- اعطای مجوز سطح پلتفرم به یک کاربر
- مقدار نامعتبر برای `effect`

### `equivalence.php` — ۸۱ مقایسه

برای هر یک از ۲۷ نقطهٔ بررسی دسترسی و هر سه نقش سیستمی، تصمیم پیش از
مهاجرت (`require_role`) و پس از آن (`require_perm`) را کنار هم می‌گذارد.

هدف این نیست که همه یکسان باشند — شش تفاوت عمدی است و در سند معماری
خواسته شده. هدف این است که **هیچ تفاوتی ناخواسته نماند**: هر تفاوت باید
در فهرست `EXPECTED_DIFFS` با دلیلش باشد، وگرنه آزمون می‌شکند.

همین آزمون در فاز ۳ یک رگرسیون امنیتی واقعی گرفت: زبان‌آموز مجوز
`attendance.view` را دارد (با محدودهٔ خودش)، پس `require_perm` تنهایی
پاس می‌شد و می‌توانست تاریخچهٔ حضور زبان‌آموز دیگری را ببیند. نتیجه‌اش
تابع `require_perm_on_user()` شد که محدوده را هم اعمال می‌کند.

## بررسی سوم

`build-dist.py` هم یک بررسی یکپارچگی دارد که به دیتابیس نیاز ندارد:
کلید مجوز تایپی، نقش ناموجود، محدودهٔ ناشناخته، و مجوز پلتفرمی چسبیده
به نقش را می‌گیرد و ساخت را متوقف می‌کند.

```bash
python3 build-dist.py
```
